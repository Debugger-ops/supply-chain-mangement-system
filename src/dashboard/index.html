System profile

A distributed inventory reservation and order-fulfillment system built around two failure modes that break real supply-chain backends: overselling stock under concurrency, and orders left half-finished when a downstream step fails.

Atomic reservation. Stock check-and-decrement runs as a single Redis Lua script, so concurrent callers — including multiple app instances — can never oversell. Verified: 500 concurrent reservation attempts against 50 units of stock accept exactly 50, every time.

Saga orchestration. reserve inventory → charge payment → schedule shipping → confirm, with an explicit, idempotent compensating transaction for every step — a failure partway through cleanly unwinds everything that already succeeded instead of leaking state.

Multi-warehouse convergence. Each warehouse consumes a shared event log through its own consumer-group cursor; a node that drops offline (simulated network partition) replays what it missed on reconnect and converges to the same state as every other node.

Node.js / TypeScript Express Redis (Lua scripts) Kafka Postgres (schema ready) Zod Vitest Docker / Kubernetes Server-Sent Events
